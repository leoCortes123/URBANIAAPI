# Urbania API - Convenciones de Desarrollo para Agente IA

## 🏗️ Stack y Runtime
- Laravel 12, PHP ^8.2
- Usar `readonly classes` para DTOs y Value Objects
- Usar `enums` de PHP cuando aplique (estados, tipos fijos)
- Autoload PSR-4: `App\` → `app/`
- **NO** añadir paquetes en composer.json salvo que sea imprescindible

## 🗄️ Base de Datos y Modelos Eloquent
- Modelos generados con **Reliese**: prefijo `Tbl` (ej. `TblPais`)
- Tabla real definida en `$table` property
- **NUNCA** modificar archivos en `app/Models` salvo petición explícita
- Son capa de persistencia pura, el dominio NO debe filtrarse
- Columnas en `snake_case` alineadas con BD
- Dominio puede usar `camelCase` mapeando en repositorio

## 🧱 Arquitectura (DDD + Clean Architecture)

### Dominio - `app/Domain/{Contexto}/`
- **Entities/**: Entidades ricas o anémicas, SIN dependencias de Laravel
- **Repositories/**: Solo interfaces. **PROHIBIDO** tipos de framework
  - No usar `LengthAwarePaginator` en dominio
  - Usar Value Objects para paginación (ej. `PaisesPage`)
- **ValueObjects/**: Paginación, identificadores compuestos, etc.

### Aplicación - `app/Application/{Contexto}/`
- **DTOs/**: `readonly class` para entrada de casos de uso
  - `CreateXData`, `UpdateXData`, etc.
  - Incluir factory method `fromRequest(array $validated)`
- **Handlers/**: Un archivo por caso de uso
  - `CreateXHandler`, `GetXByIdHandler`, `ListXsHandler`
  - `UpdateXHandler`, `DeleteXHandler`
  - Constructores con **interfaces del dominio** inyectadas

### Infraestructura - `app/Infrastructure/Persistence/Eloquent/`
- Implementaciones: `Eloquent{Entidad}Repository`
- Implementan interfaz del dominio
- Mapean Eloquent ↔ Entidad de dominio
- Relaciones Eloquent SOLO aquí, nunca en dominio

### Presentación HTTP - `app/Http/`
- **Controladores API**: `Controllers/Api/{Entidad}Controller.php`
  - **DELGADOS**: Solo manejo HTTP
  - Validación delegada a FormRequest
  - Respuestas con Resources
- **Requests**: `Requests/Store{Entidad}Request`, `Update{Entidad}Request`
  - Métodos `authorize()` y `rules()`
- **Resources**: `Resources/{Entidad}Resource.php`
  - Usar `@mixin` de entidad dominio cuando útil para IDE

## 🔌 Inyección de Dependencias
- Registrar en `AppServiceProvider::register()`
- Usar `$this->app->bind(Interfaz::class, Implementacion::class)`
- Handlers se resuelven automáticamente por contenedor
- **NO** registrar handlers salvo necesidad específica

## 🌐 API REST y Rutas
- Rutas en `routes/api.php` (prefijo `/api` por defecto)
- Recursos en **español y plural**: `paises`, `ciudades`, `usuarios`
- IDs numéricos con `->whereNumber('id')` en show, update, destroy
- Códigos HTTP:
  - `201` en creación (POST)
  - `204` en borrado exitoso (DELETE)
  - `404` con mensaje JSON cuando recurso no existe
  - `422` con errores de validación
  - `400` para errores de dominio/negocio

## ✅ Validación y DTOs
- Validar en **FormRequest**
- En controlador: armar DTO con `$request->validated()`
- Campos opcionales: usar `?? null` si no vienen en request
- Reglas alineadas con nullable/required de BD

## 📄 Paginación
- Dominio retorna **Value Object de página**
  - `{Entidad}Page` con items, total, perPage, currentPage
- En controlador: transformar a `LengthAwarePaginator` si necesita formato Laravel
- Usar `path` y `query` desde Request

## 📛 Convenciones de Nombres
- **Dominio**: Entidad singular (`Pais`)
- **Interfaz repositorio**: `PaisRepositoryInterface`
- **Value Object**: Nombre explícito (`PaisesPage`)
- **Infraestructura**: `EloquentPaisRepository`
- **HTTP**: `PaisController`, `StorePaisRequest`, `UpdatePaisRequest`, `PaisResource`

## 🧪 Pruebas
- Usar **Pest** para todas las pruebas
- **Feature tests**: `tests/Feature/Api/{Entidad}Test.php`
  - Probar endpoints completos
  - Usar `DatabaseMigrations`
- **Unit tests**: `tests/Unit/Domain/{Contexto}/`
  - Probar lógica de dominio
  - Cada handler debe tener su test
- **Naming**: `it_crea_un_pais_validamente()`, `it_retorna_error_404_si_pais_no_existe()`

## 🚫 Lo que DEBES EVITAR (Crítico)
- ❌ Usar Eloquent directamente en controladores o handlers
- ❌ Pasar `Request` a los handlers (siempre DTOs)
- ❌ Lógica de negocio en modelos `Tbl*` (modelos de persistencia)
- ❌ Usar `paginate()` de Eloquent en el dominio
- ❌ Retornar modelos Eloquent desde repositorios (siempre entidades dominio)
- ❌ Definir relaciones Eloquent en modelos (hacerlo en repositorios)
- ❌ Refactors masivos o archivos no pedidos

## 📝 Principios de Cambio (Para el Agente IA)
- **Cambios mínimos**: No refactors masivos ni archivos no solicitados
- **Sin documentación nueva**: No crear archivos markdown salvo que el usuario lo pida
- **Reutilizar patrón Pais**: Usar mismo patrón para nuevas entidades
  - Carpetas por contexto
  - Handlers completos (CRUD)
  - Repositorio con binding
  - Rutas y Resource

## 🔧 Manejo de Errores
- Crear excepciones de dominio en `app/Domain/Common/Exceptions/`
- `ResourceNotFoundException` para 404s
- `DomainException` para reglas de negocio violadas (400)
- Transformar automáticamente en `ApiExceptionHandler`

## 🎯 Eventos del Dominio (Opcional - Cuando aplique)
- Usar para desacoplar efectos secundarios
- Eventos en `app/Domain/{Contexto}/Events/`
- Disparar desde handlers después de guardar
- Escuchar en `app/Application/{Contexto}/Listeners/`
